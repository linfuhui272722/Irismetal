# AGENTS.md

## Build

- Java 25 toolchain (install `openjdk-25-jdk`). Build with `./gradlew :fabric:build -x test`.
- Output jar: `build/libs/iris-fabric-<version>.jar` (dev jar, `-local` suffix when no GITHUB_RUN_NUMBER).
- For the fork release naming convention, copy/rename to `irismetal-<version>.jar`.
- Loom uses the `jar` task (no `remapJar` task exposed in this setup); the `-local` jar is the distributable.

## Metal shader compiler gotchas (MetalShaderCompiler.java)

- `wrapLooseUniforms` moves loose non-opaque uniforms into a `MetallumIrisUniforms` UBO block and rewrites bare references to `iris_uniforms.X`.
- Multi-variable uniform declarations (`uniform float a, b, c;`) MUST be split via `splitMultiDeclarator()` so every variable name gets rewritten; otherwise non-last vars become undeclared identifiers, causing GLSL-to-SPIRV failure and a native SIGSEGV on entering a world.
- Local variable shadowing a same-named uniform (e.g. `uniform float shadowFade;` + function-local `float shadowFade = ...`) MUST be handled scope-aware in `replaceInShaderCode`: the local declaration and all in-scope references stay bare (resolve to the local), while out-of-scope references are rewritten to `iris_uniforms.X`. Otherwise the declaration becomes `float iris_uniforms.shadowFade = ...` (illegal `unexpected DOT`) and in-scope refs become illegal assignments to a uniform. Helpers: `declaresLocalVariable`/`isDeclarationStart`/`isGlslTypeKeyword` (detect GLSL typed local decls), `netBracesBeforeToken` (correct decl depth when `decl` shares a line with `{`), `countChar`.
- `declaresLocalVariable` MUST only treat `varName` as a declaration when it is the **declared name** (before the first `=` / array `[`), NOT when it merely appears on the RHS of an initializer. Earlier it used a loose whole-line regex that matched `float time = frameTimeCounter * 1.0f;` as a local declaration of `frameTimeCounter`, entering shadow scope at depth 0 which never exited, so every subsequent uniform ref in a vertex shader went unrewritten → `undeclared identifier` for `frameTimeCounter`/`cameraPosition`/`shadowProjectionInverse`/`viewHeight`/`viewWidth`. Now it strips qualifier+type (`stripTypeAndQualifiers`), splits declarators by comma, and compares only the pre-`=` name. `isDeclarationStart` also rejects `type (` (function defs/constructors).
- The declarator-list split MUST ignore commas inside `()`/`[]`/`{}` (`splitTopLevelCommas`). A naive `String.split(",")` also split constructor/initializer arguments, so `vec4 iProjDiag = vec4(gbufferProjectionInverse[0].x, gbufferProjectionInverse[1].y, ...)` was split into declarators where `gbufferProjectionInverse[1].y` (no `=`) was treated as a declared name → falsely matched `gbufferProjectionInverse` → shadow scope → all its refs unrewritten → `undeclared identifier` in `gbuffers_basic.fsh`.
- Debugging these crashes: the log has `Full shader content for <name>:` (raw source, multi-line real text) and `Adapted shader preview (first 3000 of N chars):` (rewritten source, first 3000 chars). shaderc error line numbers refer to the REWRITTEN source; account for the UBO block insertion offset.
- To reproduce/verify locally without Iris deps, copy `wrapLooseUniforms`/`replaceInShaderCode` et al. into a standalone `main` and feed it the extracted shader source; print rewritten line N to pin down the breakage.
- GitHub releases use tags like `v1.11.4-fix-vN`. Asset filenames containing `+` must be URL-encoded as `%2B` when uploading via the assets API.
- `gl_VertexID` injection (vertex shaders) MUST insert `in int iris_VertexID;` at the directive-prelude end (`findDirectivePreludeEnd`), NOT via `indexOf("uniform ")`. The latter matches the `uniform` keyword inside `layout(std140) uniform iris_CloudInfo {`, splitting the layout qualifier off and producing illegal `layout(std140) in int iris_VertexID;` (packing qualifier `std140` cannot be used on `in`/`out`). Crashed `gbuffers_clouds.vsh`.
- DH (Distant Horizons) uniform injection (`dhMaterialId`/`dhRenderDistance`) runs AFTER `wrapLooseUniforms`, so those uniforms are added to the UBO block but their bare references are NOT auto-rewritten. MUST call `replaceInShaderCode(body, name)` on the post-block body after injecting, else `int blockID = dhMaterialId;` stays bare → `undeclared identifier`. Crashed `dh_terrain.vsh`/`dh_water.vsh`.
- `replaceInShaderCode` MUST track `parenDepth` and skip the `declaresLocalVariable` check when `parenDepth > 0` (inside a function parameter list). Otherwise a function param like `float near,` in `AmbientOcclusion(...)` is misdetected as a local declaration, entering a shadow scope at depth 0 that never exits (the function body is at depth 1, so `depth < shadowDepth` is always false), leaving the call site `AmbientOcclusion(..., near, ...)` unrewritten → `undeclared identifier` for `near`/`far`. Crashed `deferred.fsh`.
- `layout(location = N) out/in` is LEGAL (location qualifier); only PACKING qualifiers (`std140`/`std430`/`row_major`/`column_major`/`packed`/`shared`) are illegal on `in`/`out`. Don't flag location-qualified declarations as errors.
- **Token/permission gotcha**: the `GITHUB_TOKEN` (GitHub App `ghu_` token) can `git push` but the Releases API and Contents API may return `403 Resource not accessible by integration` if the App installation lacks `Contents:write`. Fallback: commit the built jar to `dist/` and push, then download from `https://raw.githubusercontent.com/<owner>/<repo>/main/dist/<file>.jar`.
